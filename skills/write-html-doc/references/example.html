Storage Backends — Capability Matrix

A side-by-side of the three storage backends behind the object service, so we can pick one default per deployment tier. The short version: local disk is fastest but not durable, and the replicated store is the only safe default for production.

2Durability model

Writes fan out differently per backend. Replicated is the only one that survives the loss of a whole zone:

client ──▶ repl ──┬──▶ zone-a (quorum) ├──▶ zone-b └──▶ zone-c (async)
  • Local disk — a lost node loses unflushed writes; acceptable only for caches.
  • Replicated — acks after 2 of 3 zones; survives one zone down.

The rule

Anything a user cannot regenerate goes to repl. Local disk is a cache, not a store of record — treat a node loss as expected, not exceptional.

3Recommendation

Default per tier

Dev → local. Staging and production → repl. Backups and anything older than 30 days → lifecycle to cold.
